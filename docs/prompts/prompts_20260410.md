PDFA Web Tier Implementation Specification

Context & Objectives

Build a Flask-based web interface for the PDFA Webservices and Application project. The interface must provide a seamless, "Google-esque" user experience (minimalist, whitespace-rich, elegant) while providing full CRUD capabilities for the entities defined in the BaseDAO architecture.

Technical Requirements

Backend: Flask (Python) using the existing BaseDAO / MySQLDatabase / SQLiteDatabase implementations.

Frontend: Jinja2 Templates with Tailwind CSS (for styling). Use inline SVGs or Lucide-React equivalent icons.

State Management: Flask session to store the active_workflow_id and basic auth status.

Database Architecture: Ensure all dependent entities (Roles, Guards, Interactions) are scoped to the selected workflow_id.

Part 1: Visual Design Tokens (The "Google" Aesthetic)

To achieve the requested "Google-esque" look, the agent must strictly adhere to these design tokens:

Color Palette:

Background: #F8F9FA (Off-white gray)

Surface/Cards: #FFFFFF (Pure white)

Primary Action: #1A73E8 (Google Blue)

Border/Dividers: #DADCE0 (Soft gray)

Text Primary: #202124 (Near black)

Text Secondary: #5F6368 (Medium gray)

Typography: Use Inter or Product Sans font stacks. Body text should be 14px for high-density tables and 16px for form inputs.

Shapes: 8px border-radius for buttons and containers. 24px padding for most cards.

Elevation: Use subtle shadows for interactive elements. box-shadow: 0 1px 2px 0 rgba(60,64,67,.30), 0 1px 3px 1px rgba(60,64,67,.15);.

Part 2: Page-by-Page Detailed Requirements

1. Logon Page (/login)

Layout: Full-screen flex container, centered vertically and horizontally.

The Card: A 450px wide white card with high padding (40px).

Header: The PDFA logo (simple SVG) followed by a 24px semi-bold heading "Sign in". A secondary sub-heading "Use your PDFA Account".

Form Pattern:

Fields: Username and Password.

Interaction: Use "Outlined" style inputs where the border turns blue on focus.

Logic: Initially, any non-empty string for both fields is accepted. Upon "Next", set session['logged_in'] = True and redirect to /select-workflow.

2. Workflow Selection Page (/select-workflow)

Layout: Center-aligned container with a max-width of 1000px.

Header: A simple, large heading "Choose a workflow" and a sub-text "You must select a workflow context to manage its components."

The Grid: A responsive grid of cards (3 columns).

Card Interaction:

Display workflow_name (bold) and workflow_description (2 lines max with ellipsis).

Hover state: Entire card scales slightly (1.02x) and shadow deepens.

On Click: Triggers a POST to /set-context which sets session['workflow_id'] and session['workflow_name'].

Constraint: Access to any other page (Roles, Guards, etc.) must redirect back here if session['workflow_id'] is missing.

3. Dashboard Master Layout (/dashboard)

Header (Fixed Top):

Left: Burger menu (to toggle sidebar), PDFA Logo, and a vertical divider followed by the "Active Workflow: [Name]" badge.

Center: Search bar (visual only for now) with a light gray background and rounded corners.

Right: "Swap Workflow" button (outlined style), Help icon, and User Avatar (Initials circle).

Sidebar (Left Nav):

Elegant, thin sidebar with labeled icons.

Items: Workflows, Roles, Guards, Interactions, Interaction Components.

Active state: The selected menu item gets a light blue background and blue text/icon.

4. Entity Management Views (CRUD)

Each view (Roles, Guards, etc.) follows the same pattern:

Action Bar: A sub-header with the Entity name and a primary blue button "Create [Entity]".

The List: A high-density table.

Rows: Light border-bottom. No vertical lines.

Actions: "Edit" and "Delete" icons appear only on row hover.

The Creator Form: Use a "Slide-over" drawer from the right side of the screen.

Pattern: The form title at the top, scrollable fields in the middle, and a fixed "Save" / "Cancel" footer.

Field Requirements for Interaction Components:

Dynamic dropdowns populated from select_all_from_role_table() and select_all_from_guard_table().

Validation logic: Only show options relevant to the active workflow_id.

Part 3: State & Logic Implementation Steps

Auth & Context Middleware:

Implement a @before_app_request hook.

Logic: If endpoint is not /login and user not in session, redirect to /login.

Logic: If user is logged in but workflow_id is missing and endpoint is not /select-workflow, redirect to /select-workflow.

Context Swapping:

The "Swap Workflow" button triggers GET /swap. This clears session['workflow_id'] and redirects to /select-workflow.

DAO Initialization:

The Flask g object should hold the database connection per request, initialized from the MySQLDatabase or SQLiteDatabase classes based on config.

Error States:

If a DAO method returns return_code = -1, display an elegant snackbar/toast at the bottom left of the screen with the error message. Use a red accent for errors and blue for successes.

Part 4: Technical Stack specific instructions

Tailwind Config: Ensure border-radius is set to 0.5rem (8px).

Icons: Use lucide-static or hardcoded SVG paths for the Google-style icons (Material Design System icons).

Forms: Use method="POST" for all create/update actions. Implement CSRF protection if possible.
